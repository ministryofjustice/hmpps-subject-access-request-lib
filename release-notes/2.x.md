# 2.6.2
## Support for `optionalValue` and `optionalString` to take custom fallback text
The `optionalValue` and `optionalString` template helpers return "No Data Held" when the specified object property
has no value.  
EG: `{{ optionalValue someProperty }}` will return either the value of `someProperty` or "No Data Held"  
It is now possible to specify custom fallback text:  
EG: `{{ optionalValue someProperty 'No data recorded' }}` will return either the value of `someProperty` or "No data recorded"

# 2.2.0
## Fix date time formatting UTC offset defect
Fixed date conversion logic to apply UTC offset when present in the date time string.

Previously the DateConversions regex pattern logic matched optional offset info to a single converter.

e.g. `"2024-05-01T12:34Z"` and `"2024-05-01T12:34"` would be handled by the same converter.

The regex matching an input to a converter made it possible to match both cases to a single converter. 
However, it's not
possible to include an optional offset in the format string - to accommodate both cases the offset was omitted from the 
conversion. 

This update adds a converter for each case so the offset is applied to the output if present.

For example:
  
  - `2024-05-01T12:34Z` is output as `2024-05-01 13:34` as the offset info is present.
  - `2024-05-01T12:34` is output as `2024-05-01 12:34` as no offset info is available.

**Please Note:** This update **may** impact existing tests as date times with a UTC offset will now be converted to UK 
local time when they weren't previously.
