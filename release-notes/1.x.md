# 1.4.0
## Fix date time formatting UTC offset defect
Fixed date conversion logic to apply UTC offset when present in the date time string. Previously the DateConversions 
regex pattern logic matched optional offset info to a single converter.

e.g. `2024-05-01T12:34Z` and `2024-05-01T12:34` would be handled by the same converter.

The regex matching an input to a converter made it possible to match both cases to a single converter. However, it's not
possible to include an optional offset in the format string - to accommodate both cases the original solution omitted 
the offset from the conversion. This update adds a converter for each case so the offset is applied to the output if 
present.

For example:

- `2024-05-01T12:34Z` is output as `2024-05-01 13:34` as the offset info is present.
- `2024-05-01T12:34` is output as `2024-05-01 12:34` as no offset info is present.

**Please Note:** This update may impact existing tests as date times with a UTC offset will now be converted to UK local
time when they weren't previously.

# 1.3.0

## SarReportTest change to include stylesheet in html report

When SarReportTest has been implemented the expected report output html will now be expected to have matching standard
stylesheet css. Any tests which have implemented this test interface will need the expected html output to be updated to
account for this. Assuming no other changes have been made to the template the new expected html output can be generated
by running the implementing test with the env var `SAR_GENERATE_ACTUAL` set to `true`.
